# 独立账号与双前端重构规格

## 产品边界

- 管理端使用独立前端入口 `/admin`，只承载账号管理、运行概览和环境信息。
- 脚本工作台使用 `/workspace` 与 `/workspace/{scriptId}`，开发者和运营使用同一页面；`/workspace`
  只展示同一套资源栏和空控制台，不再维护独立首页。
- `/` 进入脚本工作台；不再提供工具首页或独立 Tool 运行页。旧 `/tools/{scriptId}` 只兼容跳转到工作台。
- 所有启用的登录用户都能看到目录和脚本名称；目录响应不得返回源码、Schema 或权限 JSON，但必须批量返回当前用户
  的查看、编辑、运行、授权及资源动作能力，让页面在点击前准确提示。
- 工作台根据脚本权限呈现锁定、仅运行、只读或可编辑能力。仅运行用户不得收到源码。
- 工作台同一时刻只挂载一个脚本控制台；脚本切换使用 URL、目录和浏览器历史，不保留隐藏工作区或顶层多 Tab。
- 目录是创建上下文：选中文件夹后从资源栏新建必须携带该 `parentId`；末级文件夹仍可新建脚本，只禁止继续增加子文件夹。
- 每次运行或调试点击都必须进入可见的未发起、执行中、完成或结果未知状态；生产或操作类脚本使用页面内确认面板，确认前不得发送请求，取消后必须明确显示未发起；结果区永久可见，仅支持放大/还原。

## 账号与管理权限

- 默认使用独立用户名密码登录；密码仅保存 Spring Security 安全哈希。
- 系统用户与本地凭证分表存储，为未来公司登录 SDK 保留真实 Adapter 的接入位置。
- 数据库没有可登录管理员时，启动 Runner 必须通过配置的初始管理员密码安全引导；不得开放“首个访问者成为管理员”的接口，也不得写死默认密码。
- 管理员可在管理端创建、停用用户、分配管理角色和重置密码。
- 管理角色只控制 `/admin/**`；不得授予创建、查看、编辑、运行或管理脚本的隐式权限。
- 会话只保存系统用户 ID；每个受保护请求重新校验用户状态，停用后立即拒绝新请求。

## 脚本权限

- 新脚本使用 permissions JSON v3，显式保存 READ、EDIT、INVOKE、MANAGE 主体。
- 新脚本创建者由服务端写入四项权限；所有启用用户均可创建脚本。
- `ADMIN`、旧全局白名单与目录 public/private 字段不得参与 v3 脚本授权判定。
- MANAGE 不隐含 EDIT，EDIT 也不隐含 MANAGE；需要组合能力时在 JSON 中显式写全。
- 只有 MANAGE 的账号仍必须能从目录进入授权面板，不得因无法查看源码而落入无操作的死路页面。
- v1/v2 保留不扩大权限的兼容读取；升级授权时写成 v3，不自动批量改写已有数据库。
- 普通保存和版本恢复不能修改权限 JSON；授权修改继续使用乐观锁和独立接口。

## 验收 seam

1. 认证 seam：启动引导、用户名密码登录、退出、会话失效与 CSRF。
2. 管理 HTTP seam：创建用户、角色范围、停用和密码重置。
3. 脚本访问 seam：目录全员可见；ADMIN 不旁路；v3 四项权限分别生效。
4. 工作台路由 seam：管理端与脚本端为两个 HTML/React 入口；`/tools/{id}` 不渲染 Tool 页面。
5. 运行 seam：仅 INVOKE 用户在工作台运行已保存版本，不能读取或提交源码；EDIT + INVOKE 才能调试草稿。
6. 本地验收 seam：`local/demo` 提供使用同一 SQLite 与本进程执行器的 `prod` 模拟目标；脚本未允许时仍可看见但不可选择，执行后结果区自动展开。

## 非目标

- 本轮不建设通用 RBAC、OAuth、找回密码邮件、验证码或认证 Provider 工厂。
- 公司登录 SDK 尚未提供时不虚构 SDK Interface；接入时复用系统用户、会话和脚本 ACL，不让 SDK 角色变成脚本权限。
- 不删除历史任务、审批、执行记录或现有 SQLite 数据。
